# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Реализовано

`POST /api/triage` проверяет JSON и непустую строку `text` до вызова AI. Некорректный ввод возвращает HTTP 400 и `{"status":"invalid_input"}`.

Результат AI проверяется на сервере в `getDraft` (`server.mjs`): ответ должен быть JSON-объектом с темой `delivery`, `pricing` или `other` и непустой строкой `draft`. В ответ API попадают только проверенные поля. Дополнительные поля модели не могут подменить `status`.

Ожидание AI ограничено 300 мс через `Promise.race`; `AbortController` отменяет работу имитатора, а таймер очищается после завершения запроса. При ошибке, таймауте или неподходящем ответе API возвращает HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Поведение `mock-ai.mjs` сохранено.

Страница показывает тему и черновик. Каждый новый запрос очищает старую тему и черновик; при сбое появляется инструкция разобрать заявку вручную. Пустая строка проверяется и на странице. На время запроса поля заблокированы, а сетевое ожидание ограничено 5 секундами; при сетевой ошибке также предлагается ручной разбор.

## Тесты

```sh
node --test
```

Зависимости устанавливать не требуется. Интеграционные тесты поднимают HTTP-сервер на свободном порту: проверяют неверный ввод, три допустимые темы, все пять сбоев имитатора, структуру ответа и таймаут даже у провайдера, игнорирующего отмену. Тесты обработчика страницы выполняют её настоящий скрипт в `node:vm` с минимальной моделью DOM: проверяют очистку старого черновика, ручной разбор при сбоях, повторную отправку и восстановление после ошибки.

Для проверки в браузере отправьте обычную заявку, затем `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]` и `[empty-draft]`: после каждого сбоя должна остаться только инструкция ручного разбора, без предыдущей темы и черновика. Затем отправьте пробелы и повторите обычную заявку.

## Польза менеджеру

Менеджер быстрее получает тему и заготовку ответа, а при сбое продолжает работу вручную без риска взять устаревший черновик; эффект можно измерить по медианному времени подготовки ответа и доле заявок, обработанных с пригодным AI-черновиком.

При реализации использован OpenAI Codex. Код и результаты проверяются исполнимыми тестами; AI не отправляет ответы клиентам.

## Исходное задание

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
